# Rules for agents in this repo

## Wording: ASD-STE100 Simplified Technical English

Write all new text in ASD-STE100 Simplified Technical English (STE). This applies to:
the plan (requirements, stories, criteria, scenarios, box titles), the product text (UI, CLI output,
error messages, the deck, the skill, docs), briefs, reports, commit messages and code comments.

The main STE rules:

- Use one word for one meaning. Use simple, common words ("use", not "utilize"; "start", not
  "initiate"; "make sure", not "ensure"). Technical names (box ids, commands, file names) stay as
  they are.
- Use only these verb forms: the infinitive, the imperative, the simple present, the simple past,
  the future, and the past participle as an adjective. Do not use "-ing" forms as verbs. Do not use
  phrasal verbs when a single verb exists.
- Use the active voice. In descriptions, use the passive voice only when you do not know who acts.
- Write short sentences: 20 words or fewer in an instruction, 25 words or fewer in a description.
  Write one topic in a sentence and 6 sentences or fewer in a paragraph.
- Write one instruction in a sentence. Write the condition first: "If the gate fails, read the
  findings."
- Use "the", "a" and "this" where possible. Do not leave out words to make a sentence shorter.
- Do not make clusters of more than 3 nouns.

Do not reword text that the owner signed (stories, criteria and scenarios with an approval or a
sign-off). A change to that text makes the approval stale. Write STE in new text only.
